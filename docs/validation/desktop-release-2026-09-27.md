测试从独立临时工作目录启动，PATH 指向空目录、不提供外部 Node 或 pnpm；不以源码 `node main.js` 代替可执行文件。实际加载控制台与 preload API，检查 renderer 无 `require`、独立窗口无控制台特权桥；加载临时 Markdown 1/2，原子保存后可见 2/2，重开独立服务后绑定仍为 2/2。Windows 额外执行本机只读进程查询，验证返回当前打包程序的可执行路径。

这些绑定由共享应用服务建立，再由实际 renderer 观察，不声称人工走完安装器、系统选择窗口或所有控制台按钮。产物自检报告会作为 Release 附件保留，含版本、平台、架构、提交和断言；不含真实对话内容或用户路径。

源码 CI 同时通过类型检查、lint、核心测试、桌面 IPC/配置策略测试和浏览器回归。分隔线 0/1/3 条目计算样式、目标锁互斥/释放/损坏、Windows 签名和公共监听负例分别覆盖。

## 签名与发布

分支 push 构建的 Mac 日志确认使用临时身份 `-` 签名，未生成 Apple 公证配置。PR 构建可能跳过签名，仅供回归；Release 必须来自 push/标签的全部成功构建。Windows 没有发布者签名。用户可能收到系统来源提示，不应关闭系统安全检查。

Release 校验要求全部六个安装/压缩附件和三个平台报告同时存在，报告版本、架构、提交均匹配后生成 SHA256SUMS；已有同名 Release 时拒绝覆盖。当前证据不将 Windows 真实 Codex Desktop 的账户、页面布局或签名兼容标为通过；不把 CI 当作原一期全部真机门禁。

本轮没有重启 Codex，没有改写用户业务 Task 或真实绑定，也没有将云端构建偷偷部署到本机。
