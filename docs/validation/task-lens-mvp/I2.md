# I2 · Codex Desktop 真机验收

**状态：验收向导已实现，真实用户 Codex Desktop 的验收结果仍未取得。** 不把向导、受控 Chromium 测试或此前 CDP 可行性反馈当作 I2 通过。当前正式台账仍为 20 / 23；T02／I2／R1 不提前勾选。

## 运行验收向导

在最新实现分支、Node.js 24.x、干净工作树上执行：

```bash
pnpm install --frozen-lockfile
pnpm build
pnpm doctor -- --cdp-port 9341
pnpm test:mac:acceptance -- --enable --interactive --cdp-port 9341
```

需要核对真实会话线索时，在最后一条命令后追加：

```bash
--session-root "${CODEX_HOME:-$HOME/.codex}" --allow-session-read
```

未授权日志的运行仍能验收清单，但 `session_candidates` 保留 blocked，不能给出完整通过。找不到应用可追加 `--app "/实际路径/Codex.app"`。

准备同一窗口内两个专用测试对话 A／B，开始时只保留一个 Codex 主窗口和一个对话输入区域。先停止 **Task Lens 进程**，不是退出 Codex；检测到现存面板或仍运行的工具 observer 时，向导拒绝接管。不要关闭仍在执行长任务的 Codex。需要测试多窗口时，向导稍后会明确提示。

向导要求真实交互终端和 `--enable --interactive`，不接受 `--approve-all`、减少循环次数、用户项目目录或自定义状态目录等捷径。`Ctrl+C` 中断时清理测试资源并记录未完成；强杀进程或断电不能保证执行 finally 清理。

## 实际执行内容

向导在系统临时目录创建独立 Git 仓库、第二个 worktree、两份同相对路径的 `docs/tasks/TASKS.md`，以及独立的 Task Lens 状态目录。不会覆盖日常绑定，也不会修改你原来的 Task 文档。终端会显示本次测试文件路径，供在面板中选择；这些绝对路径不写入报告。

| 检查 | 验证方式 | 证据类型 |
| --- | --- | --- |
| 应用、端点和代码身份 | 真实应用签名、回环监听、进程归属、Git 提交、工作树状态、实际构建产物指纹 | 自动读取 |
| A→B→A 与首次确认 | 用户在真实 Codex 面板中预览、授权并确认；向导核对实际线程身份、绑定路径、两组展开和可见计数 | 人工操作＋机器断言 |
| 文件生命周期 | 只对临时测试文件执行原子替换、删除重建、权限失败和恢复；检查真实面板与缓存提示 | 自动测量 |
| 更新时延 | 1000 项文档，20 次交替保存，保留保存到可见面板计数变化的每个原始耗时与 nearest-rank p95；目标 ≤1 秒 | 自动测量 |
| 工具重启与绑定恢复 | 停止并重新创建真实 Task Lens runtime；Codex App 保持运行 | 自动断言 |
| 50 次挂载清理 | 50 次工具启停，每次检查 DOM 根、文档流、watcher 和订阅归零，之后恢复绑定 | 自动断言 |
| 独立降级 | 停止工具的 CDP 接入后启动真实独立服务，修改临时文件、检查受保护 HTTP；用户确认独立浏览器清单 | 混合证据 |
| 多窗口、侧聊、共享文件、日志候选、宿主操作、主题、页面重载／断线、事件补偿、安全负例 | 分项操作与人工观察；逐项回答 PASS／FAIL／SKIP。第二窗口还需真实 target 存在，日志候选还需已授权的实际记录结构 | 明确标注人工证据 |

自动观察使用独立只读 CDP 客户端读取 **真正渲染的面板**，不是拿服务端计算结果冒充 UI 更新。时延包含原子保存及 25 ms 轮询开销，不表示显示器逐帧测量；事件丢失后的 6 秒补偿是独立验收项，不能用正常保存的 20 个样本替代。

向导不会发送消息、改写宿主输入、操纵宿主审批或自动重载 Codex。有关发送／审批和断线的检查由操作者在专用测试对话里完成；不能安全覆盖就选 SKIP。清理循环是 **Task Lens 启停／挂载清理**，不是 50 次自动切换 Codex 对话。

## 报告与退出码

报告写入 `test-results/mac-acceptance-*/report.json` 与 `report.md`。目录权限为 0700，文件为 0600；拒绝将报告目录符号链接当作普通输出目录。自动记录版本、代码与产物身份、每项状态、20 个原始耗时、50 轮清理结果；对话与 target 使用每次运行独立盐值的哈希，不保存盐值、正文、访问凭证或原始会话 ID。

- `0`：实际 Mac 运行的必需场景均记录为通过，测量数量／阈值／清理数据满足要求。
- `2`：失败、阻塞、未测完、人工 SKIP、脏工作树或缺少必要证据；报告保留这些状态。
- `1`：未获授权、非交互／非 Mac 环境、入口失败或报告无法保存。

报告中的 `measured`／`operator`／`mixed` 明确区分证据来源。人工 PASS 是操作者的观察声明，不是自动测试。受控 fixture 即使全部用例通过也不能生成 `acceptanceComplete: true`；缺项、缺测量、错误 A/B 身份或清理残留同样不能通过。

## 仍保留的完成要求

原有 I2 的范围不缩减：真实多窗口／侧聊、不同 worktree 同路径和共享文件、日志来源及无日志手动回退、原子保存／权限恢复、20 次时延与事件补偿、宿主操作和主题、页面重载／重连、50 次资源清理、独立降级与安全边界，均需对应证据。向导未自动覆盖的行为仍须实际观察；没有证据不能仅为了退出码 0 输入 PASS。

只做结构探测时仍可使用：

```bash
pnpm test:mac -- --enable --probe-only --cdp-port 9341
```

此旧入口保持只读探测语义，不自动执行交互验收。T02 应结合 A/B 的脱敏结构探测与向导报告补齐版本／输入基线；报告不能证明未采集到的结构。

取得真实报告后，核对代码提交与实际构建产物、原始测量、人工场景证据，再更新 T02／I2 和原 [Task 台账](../../tasks/task-lens-mvp.md)，随后执行 [R1](R1.md)。向导不自动改 Task，不上传或归档文档。验收工具自身的受控验证记录见 [I2-runner](I2-runner.md)。
