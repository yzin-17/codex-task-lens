# Mac 兼容基线与下一阶段交接

关联任务：[T02 及后续 Mac/CDP 任务](../tasks/task-lens-mvp.md)。

## 当前结论

用户已确认 Mac CDP 可行性验证通过，不重复要求证明技术路线。但本仓库尚未获得该次验证的具体 macOS／架构／Codex 版本、应用身份、DOM 结构与会话记录脱敏样例。**T02 保持未完成**；不能把参考项目字段直接标成本项目已验证的稳定选择器。

GitHub Actions 的 `macos-latest` 仅运行本项目文件、授权、持久化和 HTTP 核心测试及构建。它没有用户的 Codex App、对话或已授权端点，不能补齐此兼容基线，也不计入 I2。

## 在已授权本机补录的最小资料

| 资料 | 需要记录的内容 | 不需要提交的内容 |
| --- | --- | --- |
| 环境 | `sw_vers`、`uname -m`、Codex App 的版本号与实际安装位置 | 账户、设备序列号、主机私密标识 |
| 应用与端点 | 应用元数据／签名校验所需字段；回环监听与进程归属的已验证结构 | 凭证、完整本机进程列表、可复用的调试 WebSocket 地址 |
| 页面结构 | 主 renderer 形状；当前输入区／对话区域的最小结构、属性名、可见性；A／B 切换及歧义情形 | 对话正文、输入内容、源码、全页面 HTML |
| 会话记录 | 内部线程标识、cwd、明确文件引用与上下文切换记录的字段结构 | 完整 transcript、历史消息、`auth.json`、API Key |

可先执行只读环境命令：

```bash
sw_vers
uname -m
```

Codex 版本与应用位置以“关于”界面及实际安装为准，不预设路径或私有字段。优先使用专门的无隐私测试对话和测试目录捕获结构；线程 ID、工作目录和文档路径用一致的合成值替换，以保留 A／B 区分、相同文件和不同 worktree 的关系。

缺少多窗口、侧聊、cwd 或某个记录字段时，明确写为“未观察／不可获取”，对应能力返回 unknown／unavailable；不要自动使用主对话或最近活动记录替代。

## 接入顺序与验收边界

T02 完成后，分别实施 T08 会话记录、T10 可信端点、T11 CDP 生命周期和 T12 DOM 身份。随后完成 T18 bridge、T19 内嵌入口、T20 组合命令，最后运行 I2。每项使用原 Task 的独立范围与测试，不把缺失实现集中到真机验收任务。

当前独立面板已经可以用于监控本项目自己的 Task 文档，不等待上述适配。没有授权环境时，不操作正在执行长任务的 Codex，不强制退出，不安装主题，不修改应用包或配置，不增加一个假装通过的 `test:mac` 脚本。

当未来开启 CDP 时，仅回环地址不等于身份认证；停止 Task Lens 并不自动关闭仍运行的 Codex 调试端口。恢复普通启动应等待安全时机，由用户正常退出再启动官方应用。
